# 3rdBrain Project Content Capture

## Purpose

Preserve enough factual evidence to reconstruct 3rdBrain's real journey. Keep capture selective,
source-linked, and separate from creator strategy.

## Record Route

- [`CONTENT.md`](CONTENT.md) is the canonical entry point, current snapshot, and factual record.
- `history/` holds detailed history when the journey grows.
- [`evidence/`](evidence/) holds approved milestone screenshots and short clips.

Open `CONTENT.md` first. Load only the history files relevant to the current task.

## Update Rules

Update the record after a meaningful, source-supported release, result, decision, implementation
change, research finding, milestone, or reversal. Record dates, sources, confidence or uncertainty,
and limits. Give each factual entry one authoritative owner.

Keep the entry point concise with the current snapshot, key milestones, open questions, and an
annotated history index. When distinct phases emerge or `CONTENT.md` reaches roughly 500 to 800
lines, review whether naturally named files under `history/` would improve navigation. Preserve
every fact, rationale, outcome, content lead, date, source, uncertainty label, and asset link during
any move.

## Milestone Evidence

When a meaningful milestone has visual value, attempt one relevant screenshot or short clip through
available project tools when current permissions allow it. Review the asset for relevance,
credentials, personal data, restricted information, and material that needs redaction. Save an
approved asset in `evidence/` with a clear dated filename and link it from the milestone's
authoritative entry.

When automatic capture is unavailable, fails, or requires creator interaction, ask the creator for
one screenshot or short clip and explain which moment would be useful. Continue the factual update
while the asset remains pending. If the creator declines, record the asset as declined or unavailable
and continue. Ask again only for a new relevant milestone or when the creator requests it.

Capture a short artifact for a meaningful moment. Continuous recording is outside this workflow.
Historical entries use existing evidence and clearly identified sources. Never present a newly
created or recreated image as retrospective proof.

## 3rdBrain Evidence Priorities

- Use Git history and tags, releases, repository documentation, tests, TDD records, skill contracts,
  build tools, and collector behavior as primary evidence.
- Preserve direct commit and implementation links for material claims.
- Distinguish completed work, current state, proposed work, and unverified claims.
- Keep private deployments, credentials, personal content, and unpublished repository structure
  outside the public record.
- Treat the historical PromptOS name as context. Use 3rdBrain for the current product.

## Creator Brain Boundary

Keep project facts, evidence, decisions, outcomes, and source-backed content leads here. A separate
Creator Brain owns creator strategy, positioning, taste, storytelling, scripting, packaging, and
publishing. Later ingestion requires explicit creator authority and retains source links.
